## 3. Configuration System

### Current state

`asf_heat_pump_suitability/config/base.yaml` is loaded into a global `config` dict in `__init__.py`.

### After refactor

Keep `base.yaml` as the source of truth. Add a Pydantic Settings class in `asf_heat_pump_suitability/config/settings.py` that:

1. **Validates** the YAML on load (catches missing keys, wrong types early)
2. **Separates** two categories of paths:
   - **External source paths** — S3 paths to data the pipeline does not generate (e.g. `s3://asf-mission-data/...`, EPC files, OS boundaries). These remain hardcoded in `base.yaml`.
   - **Pipeline output paths** — files generated by the pipeline (e.g. `domestic_uprns.parquet`). These are stored in `base.yaml` as **filenames only** (no bucket/directory prefix).
3. **Resolves** pipeline output paths at runtime using two env vars:
   - `LOCAL_DEV` — defaults to `true`. When `true`, outputs go to local filesystem.
   - `OUTPUT_DIR` — the base directory for resolved output paths. Defaults to `./outputs/` when `LOCAL_DEV=true`; defaults to `s3://asf-heat-pump-suitability/outputs/` when `LOCAL_DEV=false`.

### Key behaviour: LOCAL_DEV=true (default)

- **Reads**: All external source data is always read from S3 (reads are safe).
- **Writes**: Pipeline outputs are written to `OUTPUT_DIR` (local by default). Nothing is ever accidentally written to S3 unless `LOCAL_DEV=false` is explicitly set.

### Key behaviour: LOCAL_DEV=false (cloud / production)

- Reads: S3 (as always)
- Writes: S3 under `OUTPUT_DIR`

### Settings class (sketch)

```python
# asf_heat_pump_suitability/config/settings.py
from pydantic_settings import BaseSettings
from pathlib import Path
import yaml

class Settings(BaseSettings):
    local_dev: bool = True
    output_dir: str | None = None  # resolved below

    @property
    def resolved_output_dir(self) -> str:
        if self.output_dir:
            return self.output_dir
        return "./outputs/" if self.local_dev else "s3://asf-heat-pump-suitability/outputs/"

    def resolve_output_path(self, filename: str) -> str:
        """Resolve a pipeline output filename to its full path."""
        base = self.resolved_output_dir.rstrip("/")
        return f"{base}/{filename}"

    model_config = {"env_prefix": ""}
```

### `__init__.py` backwards compatibility

Keep the existing `config` dict load from `base.yaml` in `__init__.py` for now — it is widely used and changing all call sites is out of scope. The Pydantic `Settings` object is instantiated separately and used by pipeline entry scripts. Over time, call sites can migrate to `Settings`.

## 5. Pipeline Entry Scripts

All three scripts (`uprns.py`, `add_features.py`, `run.py`) use **Typer** for CLI definitions.

### `pipeline/uprns.py`

**Purpose**: Filter all UK UPRNs to domestic-only and save the result.

**Logic** (moved from `asf_heat_pump_suitability/pipeline/transform/uprns.py` + `pipeline/run/`):

1. Load UPRN coordinates from S3
2. Filter to residential UPRNs (using EPC registers and building footprints)
3. Save result to `settings.resolve_output_path("domestic_uprns.parquet")`

**CLI args**:

- `--local-authorities` (optional): filter to a subset of LAs. Accepts the same named presets as today (`plymouth`, `greater_manchester_las`, etc.) or a space-separated list of LA codes.
- `--output-dir` (optional): override `OUTPUT_DIR` env var for this run only.

### `pipeline/add_features.py`

**Purpose**: Take domestic UPRNs and add all features required for the decision tree.

**Logic** (moved from `asf_heat_pump_suitability/pipeline/run/add_features.py`):

1. Load domestic UPRNs parquet
2. Impute property type
3. Predict block of flats classification (using trained model)
4. Load building footprints, map UPRNs to building IDs
5. Add all decision-tree features
6. Save result to `settings.resolve_output_path("uprns_with_features.parquet")`

**CLI args**:

- `--uprns`: path to domestic UPRNs parquet (output of `uprns.py`). Defaults to `settings.resolve_output_path("domestic_uprns.parquet")`.
- `--local-authorities` (optional): same as `uprns.py`.
- `--output-dir` (optional): override `OUTPUT_DIR` for this run.

### `pipeline/run.py`

**Purpose**: Orchestrate the full pipeline — run `uprns.py` then `add_features.py` in order.

**Behaviour**:

- Calls `uprns.py` first, captures its output path.
- Passes that output path as `--uprns` to `add_features.py`.
- Does **not** add any logging of its own — individual scripts log their own progress.
- Propagates non-zero exit codes from either step.

**CLI args**:

- `--local-authorities` (optional): passed through to both steps.
- `--output-dir` (optional): passed through to both steps.

**Example usage**:

```bash
# Full UK run (production, writes to S3)
LOCAL_DEV=false uv run python pipeline/run.py

# Greater Manchester only (local, writes to ./outputs/)
uv run python pipeline/run.py --local-authorities greater_manchester_las
```

## 7. Local Dev / S3 Safety

### The rule: LOCAL_DEV=true by default

The `.envrc` file should set `LOCAL_DEV=true` by default:

```bash
# .envrc
export LOCAL_DEV=true
export OUTPUT_DIR=./outputs/
```

This means:

- Anyone who uses `direnv allow` in the repo gets safe local defaults automatically.
- Cloud/production runs must explicitly set `LOCAL_DEV=false` (e.g. in the arm_orbit job config).
- There is no way to accidentally write to S3 from a laptop without actively overriding the env var.

### Reading from S3

Reads from S3 (external sources) are always allowed regardless of `LOCAL_DEV`. There is no dry-run mode for reads — data scientists should be able to read from S3 freely in local development.

### `outputs/` directory

Add `outputs/` to `.gitignore`. It is a local working directory for pipeline outputs when running with `LOCAL_DEV=true`.

## 8. Tests

### Strategy

- **Unit tests**: test individual functions in the support modules (transform, impute, model). Mock S3/external calls where necessary. No fixtures needed for unit tests — use small in-memory DataFrames.
- **Integration tests**: test each pipeline step end-to-end, using committed fixture files. Mock S3 writes with moto. External S3 reads are also mocked (moto or monkeypatch).

### Fixtures

Fixtures are small representative parquet/geojson files committed to `tests/fixtures/`. They are generated by `tests/generate_fixtures.py`, which requires real S3 access and is run manually by a developer before committing.

`generate_fixtures.py` should:

- Pull a small slice of real data from S3 (e.g. 100 UPRNs from a single grid square)
- Save to `tests/fixtures/` as named files
- Be clearly documented: "Run this script once when data sources change to refresh fixtures"

### Test files

| File                                              | What it tests                                                    |
| ------------------------------------------------- | ---------------------------------------------------------------- |
| `tests/unit/test_impute_property_type.py`         | `pipeline/impute/property_type.py` — imputation logic            |
| `tests/unit/test_transform_uprns.py`              | `pipeline/transform/uprns.py` — UPRN filtering logic             |
| `tests/unit/test_transform_outdoor_space.py`      | `pipeline/transform/outdoor_space.py` — outdoor space estimation |
| `tests/integration/test_uprns_pipeline.py`        | Full `pipeline/uprns.py` step using fixtures + moto              |
| `tests/integration/test_add_features_pipeline.py` | Full `pipeline/add_features.py` step using fixtures + moto       |

### CI test execution

```bash
uv run pytest tests/unit/ tests/integration/ --cov=asf_heat_pump_suitability
```

Integration tests that require fixture files (not yet generated) should be marked `@pytest.mark.skip(reason="fixtures not generated")` until the fixtures are committed.
